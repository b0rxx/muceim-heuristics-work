k ~ Geometric(p)

The Learnheuristic Loop
1 · Predict
White box forecasts each candidate merge
2 · Choose
BR-CWS picks a merge from the updated list
3 · Observe
Black box reveals the real cost
4 · Learn
White box is refitted with the new observation
repeat until the list is empty
STATIC CWS
Savings computed once, never updated.
LEARNHEURISTIC
Savings recomputed after every merge:
s = RC(rᵢ) + RC(rⱼ) − WB(rᵢ ∪ rⱼ)
Known real costs of the two routes minus the predicted cost of their merge.

Our Implementation

Python · NumPy · scikit-learn · same 30 CVRPLIB instances

STRUCTURE

Node, Edge, Route and Solution classes from the course CWS slides. Savings, merge and a feasibility check shared by every variant.

v1 · FAITHFUL TO THE PAPER

Algorithms 1 and 2 line by line, with the paper's names: build_vrp_sol, compute_savings, merge_routes, get_real_cost.

FAST

Algorithm 2 vectorised: all pairs of end nodes at once, merged-route features in O(1) per pair. 8× faster than the double loop on M-n200.

Black box and white box are separate objects: the solver only calls get_real_cost(route) and predict_cost(route).

v1 vs v2

v1 · THE PAPER

Algorithm 2 predicts one merged route per pair: … i | j …

The route is kept as built: no improvement after construction.

v2 · OUR EXTENSION

1 · Both directions. Predict … i | j … and … j | i …, keep the cheaper. The reverse is free: Σcₑ·Q′ₑ = Q·Σcₑ − Σcₑ·Qₑ

2 · 2-opt local search. After each construction, reverse the segment that most lowers the white-box cost, until none does. The black box reveals the real cost of changed routes and the white box learns from it.

Shared by both: black box, white box, base solution, biased selection, multi-start.

Why Direction Matters

C = 100 · A: demand 60 · B: demand 10 · 0–A = 10, A–B = 10, B–0 = 30

ROUTELOAD ON EACH EDGEΣcₑ·QₑREAL COST
0 → A → B → 070, 10, 080033
0 → B → A → 070, 60, 0210046
SAME DISTANCE, +40% COST

Drop heavy customers early and ride long edges empty.

WHEN TO REVERSE

When Σcₑ·Qₑ > ½·Q·Σcₑ: the truck is, on average, more than half full.

Against the Best Known Solutions

BKS routes (CVRPLIB) through the same black box, each in its cheaper direction. Gap = (X − BKS) / BKS, below zero = cheaper than the BKS.

The BKS is optimal for distance, not for load: v2 beats it in 28 of 30 instances, v1 in 5, static in 2.

Strengths and Open Questions
STRENGTHS
  • Modular: the learner can be swapped freely
  • Simple, fast and reproducible components
  • Quantifies the cost of ignoring decision-dependent inputs
  • New benchmark instances for comparison
OPEN QUESTIONS
  • Linear black box and linear white box: a favourable case
  • One source of dynamism: vehicle load
  • No computing times; best of 30 seeds only
  • Baseline is its own static version
  • Merge direction ignored, yet it changes the cost (our v2: −6%)

Conclusions
When decisions change the inputs, plan with predictions, not static costs.
METHOD
BR-CWS and an online regression, interacting at every merge
RESULT
Paper: ~12% cheaper routes. Ours: 3.5% (v1), 9.2% with v2. Forecasts exact in both

Appendix: Algorithm 1
solution ← one route per customer
savings ← computeSavings(solution, whiteBox)
while savings is not empty:
edge ← savings[k], k ~ Geometric(p); remove edge
if mergeFeasible(edge):
route ← mergeRoutes(edge, solution)
realCost ← blackBox.getRealCost(route)
solution.update(realCost)
whiteBox.update(route, realCost)
savings ← computeSavings(solution, whiteBox)
return solution
computeSavings: s = RC(rᵢ) + RC(rⱼ) − WB.predict(rᵢ ∪ rⱼ), for every pair of end nodes, sorted in descending order.
